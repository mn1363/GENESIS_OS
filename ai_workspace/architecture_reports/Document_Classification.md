## Notes on methodology

- **Deprecated/Duplicate** was assigned to whichever document of a same-subject pair is not the source of record. In one case (`GEN-0004`/`GEN-0005`) the higher-numbered file is actually the genuine one and the lower-numbered file is the corrupted duplicate — see `Conflict_Report.md` for that specific case. In all other duplicate pairs, the later (higher-numbered) document restates the earlier one under a fancier name and is marked as the duplicate.
- **Conflicting** was assigned where a document's own stated purpose contradicts a governing principle stated elsewhere in the corpus (self-evolving core vs. sealed core; a document declaring the architecture's final closure while later documents keep extending it).
- **Conceptual / Vision** covers documents whose content is description-only — named layers and arrows between them, with no interface, schema, or algorithm — regardless of how technical the title sounds. This is the majority of `GEN-0100` onward.
- **Implementable / Supporting** boundary: Implementable = directly needed for a first working system (planning, execution, memory, agent runtime, plugin loading, config). Supporting = valid production concerns (security hardening, cost tracking, compliance, DR) that a real system eventually needs but that aren't required to get something running.
- A handful of `GEN-0100–0129` documents (e.g. `GEN-0121_System_Bootstrap_and_Cold_Start_Protocol`, `GEN-0122_System_Event_Driven_Kernel_and_Runtime`) have titles that sound implementable but contain no more technical detail than their sibling documents in the same range — they were classified Conceptual/Vision on content, not title. If any of these turn out to contain a usable mechanism on closer inspection, they should be reclassified during Phase 1 rather than assumed usable now.
